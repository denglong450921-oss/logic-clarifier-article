# Logic Audit Reference

用于深度模式和批判模式。只在需要时读取。

## 一、论证最小单元

把重要段落转成：

```text
前提 P1
+
前提 P2
↓
机制 M
↓
中间结论 C1
↓
最终结论 C2
```

然后逐层问：

- P1/P2 是原文事实、经验判断还是未经证明的假设？
- M 是否真的能从前提推出？
- C1 到 C2 有没有多跨一步？

## 二、常见逻辑跳跃

### 1. 单因归因

```text
结果 Y
↓
作者只解释为 X
```

检查是否还有：环境、资源、选择偏差、运气、行业周期、制度等变量。

### 2. 必要条件 → 充分条件

```text
成功需要长期坚持
≠
长期坚持就会成功
```

### 3. 个案 → 普遍规律

故事可以说明“可能发生”，通常不能单独证明“普遍如此”。

### 4. 相关 → 因果

```text
A 和 B 同时出现
≠
A 导致 B
```

### 5. 幸存者偏差

只看到留下来的人成功，却没看见同样长期坚持但失败的人。

### 6. 选择性时间窗口

换一个起点/终点，故事是否仍成立？

### 7. 基准率忽略

一个机会看起来“赔率大”，但成功概率是否低到几乎无法兑现？

### 8. 概念漂移

同一个词在前后承担不同意思，例如“稳定”“价值”“竞争”“风险”。

### 9. 类比过伸

扑克、投资、进化、战争等类比可以启发，但不能自动把原领域的定律搬到人生决策。

### 10. 目标函数偷换

前面讨论“赚钱”，后面可能悄悄改成“自由”“影响力”“幸福”。检查成功标准是否变化。

## 三、反例不是为了推翻，而是为了定边界

好的批判分析不是说“有反例，所以作者错了”。而是：

```text
作者命题
↓
在哪些条件下成立？
↓
哪些条件下不成立？
↓
因此应把命题改写成多强？
```

例如：

绝对版：
> 回报越慢，竞争越小，机会越大。

边界版：
> 在真实需求存在、成果可积累且参与者对延迟回报高度折现的领域，较长兑现周期可能降低持续竞争者数量。

## 四、逻辑角色标签

可使用以下标签帮助重建文章：

- `[HOOK]` 现象/故事开场
- `[QUESTION]` 母问题
- `[OLD MODEL]` 常见解释
- `[BREAK]` 指出旧模型失效
- `[THESIS]` 核心答案
- `[DIMENSION]` 引入核心变量
- `[MECHANISM]` 解释为什么
- `[EXAMPLE]` 案例
- `[CONDITION]` 附加条件
- `[COUNTER]` 回应反例
- `[RULE]` 实践规则
- `[SYNTHESIS]` 合成统一模型
- `[RHETORIC]` 修辞强化

标签只用于内部组织或必要时展示，不要让输出变得机械。

## 五、与概率论证的边界

本文件只负责“审计现有论证”。

当任务变成：

- 帮用户自己证明 / 增强现实观点；
- 筛关键变量；
- 找证据；
- 比较方案；
- 处理最强反方；
- 做置信更新；

请转到 [probabilistic-argument.md](probabilistic-argument.md)。

两者关系：

```text
Logic Audit
= 这个论证哪里可能有问题？

Probabilistic Argument
= 怎样在现实不确定性下，重新构造一个更可信的论证？
```

不要在两个 reference 中重复维护同一套概率论证规则。
