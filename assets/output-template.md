# Logic Clarifier — Output Templates

先判断任务路线，不要把两种输出混在一起。

---

# A. Argument Reconstruction Template

## 1. 核心判断

**表层主题：** …

**真正回答的问题：** …

**作者的核心答案：** …

> 一句话：……

## 2. 总逻辑图

根据真实拓扑选择：

### 因果链

```text
问题
↓
旧解释
↓
作者指出问题
↓
新机制
↓
结论
```

### 并列维度

```text
核心问题
├─ 维度 A
├─ 维度 B
└─ 维度 C
↓
统一结论
```

### 判断树

仅当原论证真的存在二元判断：

```text
是否满足条件？
├─ NO → …
└─ YES → …
```

### 反馈环

```text
识别
↓
处理
↓
反馈
└────→ 下一轮识别
```

不要为了“二进制逻辑图”强行制造原文不存在的二元对立。

## 3. 旧模型 → 新模型

```text
旧模型：……
↓
为什么失效：……
↓
新模型：……
```

若文章没有明显模型替换，明确说“这里不是模型替换”。

## 4. 核心模块

### 模块 A：……

**子问题：** ……

```text
前提 / 观察
↓
机制
↓
中间结果
↓
作者结论
```

**成立条件：** ……

**逻辑角色：** 提出变量 / 解释机制 / 证据 / 反例 / 条件 / 汇总……

### 模块 B：……

同上。

## 5. 模块之间是什么关系？

明确判断：

- 串联；
- 并列；
- 分支；
- 汇聚；
- 反馈；
- 只是松散建议。

不要为了系统感强行串联。

## 6. 逻辑审计

只列真正影响结论的 2–5 点：

- **缺失前提：** …
- **过强表述：** …
- **因果跳跃：** …
- **隐藏比较：** …
- **关键反例：** …
- **适用边界：** …

尽量给出更严谨的改写。

## 7. Source Trace Map（按需展示）

默认内部保留。

若需要审计，可展示：

```text
N01
来源：原文第 12–18 行
relation: direct

N02
来源：原文第 33–48 行
relation: synthesized

N03
来源：无直接表述
relation: inference / gap
```

## 8. 最终压缩

### 一句话
……

### 一个公式 / 流程 / 判断系统

```text
……
```

### 以后遇到类似问题，只问这 3–5 句

```text
1. ……？
2. ……？
3. ……？
4. ……？
```

# B. Probabilistic Argument Template

## 1. 命题边界

**我要论证：** …

**适用人群 / 时间 / 条件：** …

**比较对象：** …

**判断标准：** …

## 2. 3–5 个决定性变量

```text
变量 A
├─ 最强事实 / 数据：…
└─ 机制：为什么支持结论？

变量 B
├─ 最强事实 / 数据：…
└─ 机制：为什么支持结论？

变量 C
├─ 最强事实 / 数据：…
└─ 机制：为什么支持结论？
```

## 3. 证据更新

- **支持证据：** …
- **削弱证据：** …
- **证据是否独立：** …
- **当前置信判断：** 可能 / 较可能 / 通常 / 高度支持

没有统计依据时不要给伪精确百分比。

## 4. 最大反方

**最强替代解释 / 反对意见：** …

**它能否解释同一批事实：** …

**会不会让结论反转或明显降级：** …

**因此需要增加的边界：** …

## 5. 最终有限结论

> 在……条件下，根据……证据，这个观点目前“较可能 / 通常 / 高度支持”成立；但它不等于……

## 6. 快速表达版

```text
结论
↓
范围
↓
判断标准
↓
3 个最强理由
↓
每个理由 1 个最强证据
↓
最大反方
↓
有限结论
```

# C. Mixed Task

若用户要求：

> “先厘清原文，再判断有没有道理 / 帮我增强论证。”

严格按：

```text
A. Reconstruction
↓
冻结“作者原本说了什么”
↓
B. Audit / Probability
↓
明确哪些是外部补强
```

不要把后补证据写回“作者原论证”。
